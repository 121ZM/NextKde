## 问题
- `shared/pim/src/PimClient.cpp:212-215 + 300` — 每次 `changed(revision)` 信号触发 `refresh()`（全量 snapshot），且每次 mutation 回复成功后 `handleReply` 尾部又 `refresh()`。一次写 = mutation 回复 → daemon `emit changed` → `onRemoteChanged` 再 `refresh` + 尾部 `refresh` ≈ **2 次全量 snapshot 往返**。`onRemoteChanged` 用 `>=` 比较，同 revision 也再刷一次。
- `services/pim-service/src/PimStore.cpp:470-487` — `save()` 每次 mutation 全量 `ICalFormat::toString` + 两次 `QSaveFile`。
- `PimStore.cpp:239-252` — `linkedTodoId` 对每事件 O(N) 扫 `rawTodos` → `snapshot()` O(E×T)。
- `PimStore.cpp:639-689` — `writeWidgetSnapshot` 用 `snapshot()`+`eventsForRange()` 两个完整 JSON 序列化再 parse 回取子集（CPU 浪费）。

## 改动点
- `PimClient::onRemoteChanged` 改 `revision > m_revision` 严格大于；去掉 mutation 回复尾部多余 `refresh()`（changed 已覆盖）。
- `PimStore::save()` 加 100-300ms debounce 批量落盘。
- `linkedTodoId` 改反向 map / 预建 `uid→todo` hash。
- `writeWidgetSnapshot` 直接从内存模型构造，去掉 stringify→parse 往返。

## 验证
- 连续批量编辑 N 条时写文件次数从 N×3 降到 ~3。
- 单次写只产生一次 snapshot 往返（日志/`m_pendingCalls` 计数）。

## 审查要点
- 去掉尾部 refresh 后 mutation 仍触发 UI 更新（changed 路径覆盖）。
- debounce 窗口内崩溃不丢写（QSaveFile 语义保留）。
