## 问题
1. `readDisk` 每 10s `exec.Command("df",...)`（`main.go:554`），且在 `sample()` 全局锁内（`main.go:890-930`）执行——稳态最大单项 CPU（每 10s fork+exec+动态链接）。`:545-553` 先解析 `/proc/mounts` 确认 `/` 存在是多余仪式。
2. `sample()` 全程持 `s.mu` 做 ~50 次 sysfs 读 + exec：`readTemperature` 每次 glob thermal_zone*/hwmon* 且每 `tempN_input` 额外读 `tempN_label`（`main.go:653-685`）+ `readMem`/`readDisk`/`readCPU`/`readFrequency`。锁内 5-15ms，每 10s 一次，抬高请求尾延迟、让 1s uptime 归因抖动。
3. `persist()` 持 `s.mu` 做两次完整 JSON marshal + 两次写盘（`main.go:203-217`），每 10s/天气翻转/desktop 变更触发。
4. 天气失败无退避：`weather.go:518` 跳过条件要 `Current != nil && NextRefreshAt>now`；离线无缓存时每 10s tick 都满足重刷 → HTTP + persist + 广播循环（`main.go:1126`）。
5. `state.json`/`snapshot.json` 内容近重复（`main.go:215-216`），每 10s 双写 ~50-150KB。

## 改动点
- `readDisk` 改 `golang.org/x/sys/unix` 的 `Statfs("/")`（已 import），零分配零子进程，删 `/proc/mounts` 预检。
- 采样移锁外：`readCPU` prev 改局部传参或 atomic；锁内只赋值。label/name 启动时枚举一次缓存。
- `persist`：锁内浅快照（配合 R1），锁外 marshal+写。
- 天气失败设 `NextRefreshAt = now + min(60s×2^n, 30min)`；`Error`/`Status` 未变跳过 persist/publish。
- 可考虑合并 state/snapshot 写或剔除重复 History。

## 验证
