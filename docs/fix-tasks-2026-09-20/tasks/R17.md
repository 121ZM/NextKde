## 问题
- `apps/settings/src/main.cpp:699-743` — `callShell()` 每次 IPC 都 `QProcess` + `waitForStarted(1500)` + `waitForFinished(5000)` + `QThread::msleep(120)` 重试，**全在 UI 线程**。单次失败可阻塞 ≈11.4s。
- `apps/settings/main.qml:4335-4361` — 7 个设置页**全部静态实例化**，每页 `Component.onCompleted: refresh()` → 启动时 7+ 次串行 spawn `quickshell ipc call`。Shell 不在时启动冻结 ~10-40s。
- `main.qml:497` — `IntegrationStatusPage` 有 `Timer{interval:5000; repeat}` 页面可见时每 5s 一次同步 spawn。
- `main.cpp:399-452` `integrationSnapshot()` 同线程做 2 个同步 D-Bus + `/proc` 读。
- slider 拖动经 60ms debounce 后调 `updateGlobalBlurStrength`，每次拖动潜在 5s 卡顿。

## 改动点
- `callShell` 改异步：`QProcess::start` + `finished` 信号回调，或 `QtConcurrent::run`+回调，或直接 `QLocalSocket`/D-Bus 连 shell（去掉每次 spawn）。
- QML 改"发请求→snapshotChanged 信号驱动 UI"模型（参考 `WeatherClient`/`PimClient`）。
- 7 页改 `Loader active: currentPage===N` 惰性实例化，进入时才 refresh。
- `integrationSnapshot` 的同步 D-Bus 移出 UI 线程或异步化。

## 验证
- Shell 不在时启动不再冻结；slider 拖动不卡。
- 各页数据仍能正确刷新。

## 审查要点
- 异步回调里对 UI 状态的更新在 UI 线程。
- 页面 LazyLoad 后 `refresh()` 触发时机正确（避免空页）。
