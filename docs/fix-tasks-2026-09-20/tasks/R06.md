# R6 · daemon 裸 D-Bus `call()`/`property()` 加超时（消 25s 冻结）

| 字段 | 值 |
|---|---|
| 阶段 | 一 |
| 并发组 | C（PlatformServer.cpp 串行链首） |
| 依赖 | 无 |
| 优先级 | P0 |
| 分支 | `fix/2026-09-20-daemon-dbus-timeout` |

## 问题
`PlatformServer.cpp` 多处阻塞式 `QDBusInterface::call()`/`property()` 无 `setTimeout`，走 ~25s 默认超时，全部冻结单事件循环：
- `:2902` `effect.call(method)` → DockWindowAnimation
- `:2929` `bridge.call("activeApplicationMenu")`
- `:2965/2991/2998` `menu.call(...)` → 任意第三方应用 dbusmenu（可被恶意/卡顿应用 hang 25s）
- `:3031` `effect.call("paste")`
- `:3102/3163/3172` `nightLight.call("inhibit"/"uninhibit")`
- `:3183/3711` `kwin.call("reconfigure")` — KWin 合成忙时冻结整个 daemon
- `:3697` `login1 SetBrightness`
- `:3794/3854` `effects.call("reconfigureEffect")`

`dbusGetAll` 已有 `kDbusCallTimeoutMs=2000`，但上述路径没设。

## 改动点
- 统一给所有裸 `call()`/`property()` 设 `setTimeout(kDbusCallTimeoutMs)`。
- 慢路径（appmenu layout、KWin reconfigure）改 `asyncCall` + `QDBusPendingCallWatcher`。
- 超时返回结构化错误而非冻结。

## 验证
- 模拟对端 hang（如伪造 appmenu 不应答），断言 daemon 仍响应其它请求。
- 各受影响功能（亮度/夜灯/appmenu/reconfigure）正常。

## 审查要点
- 改 async 的调用是否仍正确处理 reply/错误。
- 是否漏掉某个裸 call（grep `\.call(\|\.property(` 复核）。
